## M1 — Profiles, uploads, validation

- **JWT auth added**, even though `claude.md`'s milestone breakdown doesn't call it out as an M1 task explicitly — the API contract (§6) states "JWT auth except `/internal/*`" for every route, and M1 is where the first user-facing endpoints beyond `/healthz` exist. Minimal single-user implementation: `POST /api/v1/auth/login` checks the email against `FOUNDER_EMAIL`, get-or-creates that one `User` row, issues a 30-day JWT. No refresh flow — not needed for a single-user local tool.
- **Split S3 endpoint config** (`S3_ENDPOINT` vs `S3_PUBLIC_ENDPOINT`): the API container reaches MinIO via the docker network hostname (`minio:9000`), but a presigned URL's signature is bound to the host it's signed for — so a URL signed against `minio:9000` would be unusable by a browser/host machine, which has no DNS entry for `minio`. `S3_PUBLIC_ENDPOINT` (only set in `docker-compose.yml`, defaults to `S3_ENDPOINT` otherwise) is used exclusively for presigning; the internal endpoint handles all server-side object operations. In production (Cloudflare R2) both will be the same single public URL, so this only matters for local dev.
- **Face/hand detection uses MediaPipe's legacy `solutions` API** (`face_detection`, `hands`), not the newer Tasks API. The Solutions API bundles its models inside the pip package, so no runtime model download is needed — simpler and more reliable in a Docker build with no guaranteed network access at container-run time.
- **Frame extraction's "frontal-ness" score is a simplified heuristic** (eye/nose-tip horizontal symmetry from MediaPipe's 6 face-detection keypoints), not full head-pose estimation. `claude.md`'s M1 acceptance criteria only requires golden fixtures to pass and a bad photo to be clearly rejected — not a validated head-pose model. Revisit if the auto-selected primary reference photo turns out to pick poor angles in practice.
- **Photo sharpness threshold is a fixed absolute cutoff (100, variance of Laplacian)**, per `claude.md`'s explicit "start ~100" guidance — not a bottom-decile relative comparison, since M1 validates each upload independently rather than against a batch.
- **Voice sample validation is a standalone endpoint check** (duration ≥30s + `ffmpeg volumedetect` loudness check on an uploaded `voice_sample` asset). The "extract audio from the reference video as a fallback when no separate voice sample exists" behavior described in `claude.md` M1 is actually exercised at voice-clone time — deferred to M2 where it belongs.
- **Verified end-to-end locally** (`docker compose up --build`): login → profile create → presigned upload → PUT direct to MinIO → asset validation, using a deliberately bad synthetic photo (200x200, blank, no face). All three expected rejections fired with clear messages: low resolution, blur, no face detected. The "golden fixtures → all-green checklist" half of M1's acceptance criteria is still pending — needs the Director's real photo/video/audio fixture files.
