## M1 — Profiles, uploads, validation

- **JWT auth added**, even though `claude.md`'s milestone breakdown doesn't call it out as an M1 task explicitly — the API contract (§6) states "JWT auth except `/internal/*`" for every route, and M1 is where the first user-facing endpoints beyond `/healthz` exist. Minimal single-user implementation: `POST /api/v1/auth/login` checks the email against `FOUNDER_EMAIL`, get-or-creates that one `User` row, issues a 30-day JWT. No refresh flow — not needed for a single-user local tool.
- **Split S3 endpoint config** (`S3_ENDPOINT` vs `S3_PUBLIC_ENDPOINT`): the API container reaches MinIO via the docker network hostname (`minio:9000`), but a presigned URL's signature is bound to the host it's signed for — so a URL signed against `minio:9000` would be unusable by a browser/host machine, which has no DNS entry for `minio`. `S3_PUBLIC_ENDPOINT` (only set in `docker-compose.yml`, defaults to `S3_ENDPOINT` otherwise) is used exclusively for presigning; the internal endpoint handles all server-side object operations. In production (Cloudflare R2) both will be the same single public URL, so this only matters for local dev.
- **Face/hand detection uses MediaPipe's legacy `solutions` API** (`face_detection`, `hands`), not the newer Tasks API. The Solutions API bundles its models inside the pip package, so no runtime model download is needed — simpler and more reliable in a Docker build with no guaranteed network access at container-run time.
- **Frame extraction's "frontal-ness" score is a simplified heuristic** (eye/nose-tip horizontal symmetry from MediaPipe's 6 face-detection keypoints), not full head-pose estimation. `claude.md`'s M1 acceptance criteria only requires golden fixtures to pass and a bad photo to be clearly rejected — not a validated head-pose model. Revisit if the auto-selected primary reference photo turns out to pick poor angles in practice.
- **Photo sharpness threshold is a fixed absolute cutoff (100, variance of Laplacian)**, per `claude.md`'s explicit "start ~100" guidance — not a bottom-decile relative comparison, since M1 validates each upload independently rather than against a batch.
- **Voice sample validation is a standalone endpoint check** (duration ≥30s + `ffmpeg volumedetect` loudness check on an uploaded `voice_sample` asset). The "extract audio from the reference video as a fallback when no separate voice sample exists" behavior described in `claude.md` M1 is actually exercised at voice-clone time — deferred to M2 where it belongs.
- **Verified end-to-end locally** (`docker compose up --build`): login → profile create → presigned upload → PUT direct to MinIO → asset validation, using a deliberately bad synthetic photo (200x200, blank, no face). All three expected rejections fired with clear messages: low resolution, blur, no face detected.
- **Photo sharpness is scored on the detected face region, not the whole frame** — found via real fixture testing: all 3 of the Director's genuinely-in-focus real photos were rejected as "blurry" because a large plain white background behind a zoomed-in portrait drags the frame-wide Laplacian variance down regardless of whether the face itself is sharp (whole-frame scores were 62-83; the same photos' face-region scores were 90-141). Whole-frame scoring is the wrong signal for "is the person in focus" on exactly the zoomed-in shots `claude.md` asks for. Fixed by detecting the face first, then computing sharpness only on that crop; falls back to whole-frame scoring when face count isn't exactly 1 (already fails for other reasons in that case). Frame extraction's candidate scoring got the same fix, for consistency.
- **Video frame rotation correction was a critical, non-obvious bug** — the Director's real reference video (iPhone, portrait, HEVC/MOV) is stored as 3840×2160 raw sensor frames with a `rotation: 90` flag in its Display Matrix side-data. `cv2.VideoCapture` decodes the raw (sideways) frames and silently ignores that flag. Every face/hand detection in this milestone was running on 90°-rotated frames — `single_face_ratio` measured **7.7%** on the real video despite the Director's face being in frame the whole time; `hands_ratio` (88.5%) looked fine only because MediaPipe's hand detector tolerates rotation far better than its face detector does. Fixed by reading the rotation from `ffprobe`'s `side_data_list` (falling back to the legacy `tags.rotate` field for older files) and rotating each decoded frame back to upright — via `cv2.rotate()` — before any detection or scoring runs, in both `media_validation.py` and `frame_extraction.py`. **Rotation direction (90 → `ROTATE_90_COUNTERCLOCKWISE`) was verified empirically**, not assumed: extracted a raw frame, rendered both rotation directions, visually confirmed which one was upright before writing the fix. After the fix, `single_face_ratio` on the same real video went to **100%**. This is very likely to recur with every phone-recorded portrait video, so it's not a one-off — any future validator/extractor touching raw video frames must account for rotation metadata.
- **Golden fixture media lives in `assets/test/` locally but is *not* committed to git** — deviates from `claude.md`'s literal repo layout, which shows `assets/test/` as part of the tracked repo. Two reasons: (1) the real reference video is ~190MB, and GitHub hard-rejects any file over 100MB without Git LFS — committing it as-is would simply fail; (2) it's the Director's actual face/voice, and there's no need to carry personal media in git history indefinitely just to have fixtures available. Only the small text fixtures (`script.txt`, `emotion_brief.txt`) are tracked; photos/video/audio are `.gitignore`d and stay local-only. If Git LFS becomes worth adopting later (e.g., a second machine needs the same fixtures), revisit this.
- **Golden fixtures verified for real** (2026-08-19), closing M1's acceptance criteria in full: 3 of 5 real candidate photos passed (2316×3088, resolution/face/zoom all clean — the other 2 correctly failed sharpness, and visually are in fact slightly softer); the real 51.5s/4K/24fps reference video passed after the rotation fix, with `single_face_ratio=1.0` and `hands_ratio=0.885`; 12 frames were extracted and the auto-selected primary reference frame was visually inspected — upright, sharp, natural; the real 54.6s voice sample passed (mean volume -16.3dB). Consent confirmed via the live API. **Final checklist on the test profile: `ready=true`.** M1 is fully closed.
